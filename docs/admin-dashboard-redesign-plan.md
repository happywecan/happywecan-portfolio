# 企業官網後台重構計畫書

## 1. 目標

將目前集中在單一 `/admin` 長頁面的管理介面，重構為可長期維護、適合企業官網內容營運的後台系統，同時保留既有 API 與內容管理能力。

本次重構的核心目標：

- 建立清楚、可擴充的後台資訊架構。
- 降低管理者尋找功能與編輯內容的時間。
- 統一表單、表格、錯誤提示和危險操作的互動模式。
- 改善桌面與手機尺寸的可用性。
- 補足企業後台常見的安全、發布與操作治理能力。
- 分階段交付，避免一次性重寫造成既有功能中斷。

## 2. 現況與主要問題

目前後台已具備登入、網站設定、首頁內容、作品、文章、技能、興趣、聯絡訊息及電子報訂閱者管理功能，但存在以下問題：

- 所有模組排列於同一頁，頁面過長且缺乏定位能力。
- 沒有側邊導覽、麵包屑與一致的頁面標題區。
- Dashboard 沒有摘要指標、近期內容與待處理事項。
- 大型設定表單缺少分組導覽、未儲存提醒及區塊化儲存。
- 管理表格缺少一致的搜尋、篩選、排序、分頁與空狀態。
- 刪除、錯誤、成功與載入狀態在不同模組之間不完全一致。
- 手機版表格與複雜表單的操作空間不足。
- 尚未建立角色權限、操作紀錄與完整的發布流程。

## 3. 目標資訊架構

```text
/admin
├─ 儀表板
├─ 網站內容
│  ├─ 首頁內容
│  ├─ 作品集
│  ├─ 部落格
│  ├─ 技能
│  └─ 興趣
├─ 客戶互動
│  ├─ 聯絡訊息
│  └─ 電子報訂閱者
├─ 媒體庫
├─ 網站設定
└─ 帳號與安全
```

桌面版使用固定側邊欄；行動版改為可收合抽屜。每個頁面提供一致的：

- 頁面標題與說明。
- 麵包屑。
- 主要操作按鈕。
- 載入、錯誤、空資料與成功狀態。
- 權限與危險操作提示。

## 4. 頁面與功能規劃

### 4.1 儀表板

- 顯示作品、文章、未讀聯絡訊息與訂閱者總數。
- 顯示最近更新內容。
- 顯示待處理聯絡訊息與草稿文章。
- 提供常用捷徑，例如新增作品、撰寫文章與編輯首頁。

### 4.2 內容管理

- 每種內容使用獨立路由與一致的列表頁。
- 列表支援搜尋、狀態篩選、排序與分頁。
- 新增與編輯使用獨立頁面或大型對話框。
- 支援草稿、預覽與發布狀態。
- 離開未儲存表單前顯示提醒。
- 刪除前顯示內容名稱與二次確認。

### 4.3 網站設定

將大型設定表單拆分為：

- 品牌與基本資訊。
- 聯絡方式與社群連結。
- 導覽與區塊標題。
- 首頁區塊排序與顯示狀態。
- Intro Splash。
- SEO 與分享資訊。

各分類可獨立儲存，並顯示最後更新時間及儲存結果。

### 4.4 客戶互動

- 聯絡訊息增加已讀、未讀與處理狀態。
- 提供搜尋、日期篩選及聯絡信箱快速複製。
- 電子報訂閱者提供訂閱日期、狀態與匯出能力。
- 涉及刪除或批次操作時必須二次確認。

### 4.5 帳號與安全

- 顯示目前登入帳號與登出入口。
- Token 過期時統一導回登入頁並顯示原因。
- 後續加入角色權限：管理員、編輯者、檢視者。
- 後續加入重要操作紀錄與最後登入資訊。

## 5. 設計系統

建立後台專用的共用元件，避免各管理模組重複定義樣式：

- `AdminShell`
- `AdminSidebar`
- `PageHeader`
- `DataTable`
- `FormField`
- `StatusBadge`
- `EmptyState`
- `LoadingState`
- `ErrorState`
- `ConfirmDialog`
- `Toast`

視覺延續前台黑白、俐落的品牌調性，但後台優先考量閱讀性與操作效率：

- 深色介面維持足夠的文字對比。
- 主操作使用一致的品牌色。
- 危險操作只使用紅色。
- 狀態不能只依賴顏色，必須搭配文字或圖示。
- 鍵盤焦點清楚可見。
- 表單錯誤顯示於對應欄位附近。

## 6. 技術調整

- 使用 Next.js App Router 建立 `/admin/*` 巢狀路由。
- 將驗證與版面配置集中到 `admin/layout.tsx`。
- 將 Token 失效處理集中於 API client，避免每個元件重複導頁。
- 建立統一的資料請求、錯誤與載入狀態介面。
- 優先沿用既有後端 API；需要搜尋、分頁或狀態欄位時再擴充 API。
- 桌面與行動版皆納入瀏覽器驗證。

## 7. 分階段執行

### 第一階段：後台骨架

- 建立 Admin layout、側邊欄、頂部列與行動版導覽。
- 拆分各管理功能路由。
- 集中登入驗證與 Token 過期處理。
- 保持既有 CRUD 功能不變。

### 第二階段：一致化元件

- 統一頁面標題、表單欄位、按鈕、狀態與確認視窗。
- 統一列表的載入、錯誤、空資料與成功回饋。
- 改善響應式表格與手機版操作。

### 第三階段：管理效率

- 加入搜尋、篩選、排序與分頁。
- 加入草稿、預覽、發布及未儲存提醒。
- 建立 Dashboard 摘要與近期活動。

### 第四階段：企業治理

- 加入角色權限。
- 加入操作紀錄。
- 加入 SEO、媒體庫及內容發布稽核能力。
- 完成可用性、無障礙與安全檢查。

## 8. 驗收標準

- 管理者可在兩次點擊內進入任何主要功能。
- 每個功能皆有獨立 URL，可重新整理及直接開啟。
- 所有 CRUD 操作都有明確的載入、成功與失敗回饋。
- 危險操作均有二次確認。
- Token 過期不會形成重複 API 請求。
- 重要表單離開前可偵測未儲存內容。
- 360px、768px、1440px 寬度下無不可操作區域。
- 鍵盤可完成主要操作，焦點狀態清楚。
- 既有前台資料呈現及後台 CRUD 回歸測試通過。

## 9. 建議優先順序

先完成第一階段與第二階段，讓後台從單頁工具轉為正式管理系統；搜尋、發布流程、角色權限與操作紀錄則依實際使用人數和內容量逐步加入。
